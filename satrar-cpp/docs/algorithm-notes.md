
# SatRAR algorithm notes

The Figure 1 fixture identifies the paper gates by signed AIG literals. Figure 5 maps to a target fault, postdominator output faults and dominant-side MA decisions. Figure 6 uses a reversible propagation trail: downstream requirements are added first, followed by fault excitation or a trial. Common prefixes retain assignments and their reasons.

- A target pin fault modifies only the specified input edge. The good/faulty miter uses positional PI sharing and detects any differing PO. Discovery obtains sound MAs through gate implications and structurally unaffected side inputs. For reconvergence, the projection miter keeps the fanin of affected outputs and shares unaffected nodes between both copies. A separate full-miter SAT query is available through the fault command.
- Output postdominators are computed against a virtual sink containing all PO drivers. Cycles are checked from the proposed destination towards the source.
- The native AIG propagator registers the implications of each AND on incident signals. Backtracking restores state and recorded reasons. Recursive levels split unresolved gate justifications and intersect feasible branches. L0 performs direct propagation only.
- SRAR_Wire uses opposite MAs and single-root conflicts under individual target assignments. SRAR_Gate uses the new assignments on each trial's propagation trail to find reverse implication gates and conflict-supported conjunctions. SRAR_Cir (`sub`) also checks AND–OR expressions: it keeps the dominator-derived literals as OR operands, proves on the target side that they cannot all hold, shrinks the operand set, and keeps only the trial decisions that the dominator side actually used.
- Conflict learning stores the clause `¬(context roots ∧ trial decisions)`, i.e. every fault and trial premise, so it is a circuit entailment and not a scoped fact. The clause is installed immediately after the trial is undone: it can fire as a unit or a conflict at the current level, and learned units are replayed after backtracking. A run always starts cold (`resetSolver`). `gate_nolearn` only skips installation; conflict-supported candidates are still emitted. The implication filter applies within the current dominator context and is cleared when a learned clause changes the base.
- One budget (`maxTrials`) counts outer trials, recursive-learning branches, Theorem-3 operand probes and operand-deletion retries. When it is exhausted no new branch starts; candidates whose proofs were already completed remain, and the statistics record the step (`trial`, `split`, `sub_probe`, `sub_shrink`) and scope (`target` or `dominator:<var>`).
- Discovery conservatively uses signals outside the target receiving gate's affected cone, so the added expression keeps its value when the target fault is injected. This can reduce coverage relative to the paper. Default multi-decision depth is 2, and a per-target trial budget is recorded when reached.
- Addition wraps the chosen AIG gate output and keeps the original target pin in place. Removal ties that pin to the verified stuck value before simplification and dead-logic sweep. CaDiCaL verifies each transition separately. For SAT, the returned PI model must replay a differing PO. Unknown, timeout, backend errors and invalid input never accept a candidate.
- Experimental discovery uses AIG decomposition and this implementation's propagation and filtering. Treat its counts and performance as AIG results with the recorded input, options and platform.
